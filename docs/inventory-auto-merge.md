## 設定と画面

ホーム左上メニュー → マイページ → 食材の登録 →「同じ条件の在庫へ自動合算」。初期オン。オフにすると今後の追加を別ロットへ保存する。既に合算した数量を自動で分割する設定ではない。端末内UserDefaultsの `automaticallyMergeInventory` に保存し、データ全削除で初期状態へ戻る。テストは専用UserDefaults・メモリ内DBを使う。

手入力の新規登録は見出しを「追加する量」にし、同じ条件の在庫がある場合だけ「現在200g＋追加300g→500g」の確認表示を置く。音声の追加も合算結果を表示する。レシートと音声の行ごとの合算トグルは廃止し、共通設定を使う。レシートの合算表示は「保存・期限」を開いたときだけ表示する。

## 合算の条件

`InventoryAddition` を `App/Data/InventoryService.swift` に置き、手入力・レシート・音声の「買った／追加」・買い物からの登録・レシピ詳細からの登録・初期在庫一括登録で共有する。

| 条件・入力 | 動作 |
| --- | --- |
| 同じ食材ID・保存方法・期限日・期限種別、換算可能な正確量 | 数量を合算。200g＋0.3kg→500g |
| 同じ条件の「あり」同士 | 同じ在庫行へまとめる |
| 「あり」「少なめ」「なし」の追加 | 既存と追加のうち存在を強く示す状態を保持。数量は推測しない |
| 正確量と「あり／少なめ」 | 正確量と量不明の追加分を分けて保持 |
| 既存在庫が0／なし | 同じ条件なら行を再利用。購入日は今回の追加日にする |
| 保存方法・期限日・期限種別が違う／片方のみ期限あり | 分ける |
| g・kg、ml・L以外の異なる単位 | 推測換算しない。中身のある在庫は分ける |
| 在庫の編集、音声の残量指定・棚卸し・消費 | 従来どおり指定量への変更／対象在庫からの消費。合算しない |

期限はユーザーのカレンダー上の同じ日かを比較する。同じ日の異なる時刻は同じ期限として扱い、元の期限の時刻を維持。期限種別は未指定・賞味・消費を区別する。購入日が違ってもそれ以外の条件が合う場合は合算し、残量のある在庫の購入日は古い日を保持する。

複数の既存在庫が候補になる場合は、残量のある候補を先に選び、その中で作成日時・IDで安定して選ぶ。プレビューと保存で同じ順序を使用する。既にある複数ロットの一括整理や起動時のデータ書き換えは行わない。取り除いた在庫は合算先にせず、自動復元しない。

食材IDを基準にするため豚もも肉と豚こま肉は合算しない。カスタム食材も同じIDだけが対象で、新しく作った別IDを名前だけで同一視しない。買い物で調味料の状態を指定したときは、従来どおり指定した「あり・少なめ・なし」へ更新する。

## 保存

各登録処理の既存トランザクション内で合算し、数量・更新版・履歴を同時に保存する。失敗時は全体をロールバック。レシート・音声の同じセッションや購入品の二重反映拒否は保持。合算は既存在庫IDを維持するため、通知もその在庫を参照する。内部の操作復元では合算前の数量・購入日へ戻せる。保存スキーマ・食材ID・レシピ・画像・署名設定は変更しない。
