# 複数献立・作り方・コンパクトな在庫確認

2026-10-07。開発場所は `${HOME}/Developer/IOSアプリ制作`。

## 操作

- レシピ詳細で「献立に加える」。別の料理を選んでも前の献立を残す。同じレシピの選択を重複させない。
- ホームの「決めた献立」に料理別の48pt画像と人数を並べ、それぞれ「作り方を見る」「作った」「解除」を用意。
- 「作り方を見る」で人数・時間・材料付き手順を表示する。本のアイコンを使用。開く／横に切り替える操作は献立状態・在庫を書き換えない。過去のcooking状態は有効献立として保持する。各手順のチェックは料理IDごとに画面内で保持し、閉じて開き直すと戻る。
- 「作った」から調理後の一覧へ進む（読み上げは「作った・在庫を確認」）。「その他」から在庫を変えない完了へ進める。在庫更新の取り消しを保持する。
- 解除は対象の献立だけ。対象の未購入行だけを削除する。購入チェック済みの未登録品は手動品へ切り替え、冷蔵庫への登録を続けられる。登録済み品・他の献立・手動品・在庫は残す。

## 在庫確認

通常は食材名と「使用量 → 残り」だけ。変更したい行を展開して使った量／残りの量を編集する。数量不明の食材は、状態と実測残量の任意記録を保持。調味料は3状態だけで変更でき、開いただけでは数量在庫を状態在庫へ変換しない。必要量を超える、数量・単位が不明などの場合は安全確認を保持し、無理に減算しない。予定使用量を確認して「記録して完了」で一度に保存する。

## 絞り込みと並び順

ホームの料理種類メニューを「ほかの候補」から「今日のおすすめ」の右へ移動。大きな文字では縦に配置する。食材条件は従来の「食材を選ぶ」で設定し、種類メニューと組み合わせる。

標準食材の初期順は、利用可能な在庫ありを先頭に、肉 → 魚 → 野菜 → きのこ → 卵・乳 → 豆製品 → 主食 → 加工品 → その他 → 調味料。同じカテゴリは名前順、同名なら固定キー順。期限切れ・削除済み・量0・「ない」は在庫ありに含めない。検索・別名・在庫／種類の絞り込みは保持する。絞り込みパネルの初期状態は閉じたまま。

## 保存と計算

献立状態は `selected / cooking / cooked / cancelled`。既存の終了履歴も保持。選択時の材料・人数に合わせた量を `MealSelection.ingredientPlanData`（任意Data）へ保存する。既存レコードはnilのまま移行でき、予約計算時は同梱レシピから読み取る。

新しく選ぶ料理の買い足し計算では、先に選んだ有効献立が使う予定の正確在庫を計算上だけ差し引く。実在庫を変更するのは調理完了時。単位の推測換算、曖昧在庫の量の推測はしない。調味料などpresence材料は数量予約しない。調理時は常にその時点の実在庫で再検証する。

他の献立の買い物行は、解除や人数変更でも自動で書き換えない。購入量を手で編集した結果を保つため。解除により在庫の取り分が空いた場合、既に選択済みの料理の買い物量は手で調整でき、献立を解除して選び直したときは再計算する。
