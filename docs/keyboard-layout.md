# 認識入力画面のキーボード完了操作

音声の文章・候補の食材名・数量、レシートの食材名・数量を入力している間、保存ボタンの上に「入力を完了」を表示する。タップするとフォーカスとキーボードを閉じ、文章・候補・数量は保持する。完了操作は保存や確認の代わりにはならない。各項目の確認後だけ保存でき、閉じる操作では未保存内容の破棄を確認する。

## サイズ警告の切り分け

前回の全107件テストでは`Invalid frame dimension (negative or non-finite).`が6件出ていた。レシートの確認／手入力／撮影と、音声の同意後／手入力への切り替えで発生していた。

音声の同じUIテストで、キーボード用ToolbarItemGroupからSpacerだけを除いても警告は残った。キーボード用ツールバーを外すと警告が消えた。iOS 27のこの画面構成での実測であり、SwiftUI内部の全バージョン共通の原因を断定するものではない。

入力完了の操作を失わないよう、両画面のキーボード用ツールバーを除き、FocusStateとsafeAreaInsetの下部操作へ移した。入力していないときに余分な完了ボタンを表示しない。完了ボタンのタップ領域は最低44pt。レシートは候補UUIDと食材名／数量の組合せでフォーカスを識別し、音声は文章／候補UUIDの食材名／数量を区別する。保存・破棄時もフォーカスを解除する。

SwiftDataのモデル・スキーマ、同梱JSON、認識処理、購入・調理・Undoの保存処理は変更していない。

## 自動検証の対象

- レシート：同意／取り消し、同意なしの入力・破棄、撮影の中止／採用→OCR→確認→保存、カメラ拒否後の手入力保持・写真選択の代替、説明の更新と在庫保持。
- カメラ拒否の既存UIを拡張し、名前と正確数量を入力してそれぞれキーボードを閉じても値を保持すること、確認後に2個を保存することを確認する。
- 音声：同意／破棄／取り消し、文章から追加と使用量変更、確認と在庫対象の選択。
- 新規UIは日本語文章を実際に入力し、完了操作でキーボードが閉じても文章を保持すること、候補の数量入力でも完了操作が使えること、未確認の保存禁止と破棄後の在庫不変を確認する。

通常ストアの代わりに、既存の`--ui-testing`によるメモリ内DBと専用UserDefaultsを使う。実際のカメラ・マイク・音声認識・OS許可を変更しない。

実機とiOS 17、大きい文字、外付けキーボードでの動作確認は残る。入力欄が画面下端にある場合は、スクロールして操作できる位置へ出す。UIテストもFormのアクセシビリティ上のisHittableだけを頼らず、固定の保存操作と重なる位置の入力欄をスクロールしてから操作する。
