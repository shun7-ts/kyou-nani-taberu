# 狭い画面の認識入力

## 対象と変更

iPhone SE（第3世代）の専用シミュレータを作成し、375×667pt、iOS 27.0で検証する。標準サイズと最大のアクセシビリティ文字サイズを使い、アプリプロセスの起動引数だけで文字を変更する。

音声・レシートの入力中は下部操作を「入力を完了」に絞り、保存操作はフォーカスを解除してから表示する。初回テストは音声入力で成功したが、目視では文章末尾が保存ボタンに隠れていた。入力欄の中心だけの可視判定を上下端の確認へ強め、入力中の表示領域を確保する。フォントを縮小・上限固定しない。入力値、確認条件、保存サービス、SwiftDataモデル、同梱JSON、同意やOS権限の扱いは保持する。

保存後のUndo案内は、各タブのNavigationStackとVStackで縦に配置し、案内の高さをコンテンツの外側へ確保する。以前のNavigationStack外側のsafeAreaInsetでは、iPhone SEの設定詳細で同意取り消しの最終行が案内の下へ隠れ、最後までスクロールしても届かなかった。案内を表示したまま設定詳細の同意取り消しへ到達できること、タブ移動と編集・購入・調理のUndoを検証する。取り消し処理や履歴は変更しない。

UIテストは画面内のフォーム領域へスクロールしてから操作する。一括登録・最大文字のレシート追加は、画面外や固定ボタンの裏にある項目を押していた。保存の有効化や初期登録画面の終了も検証する。上部へ戻る際は、項目が仮想化されて存在しない場合でも下向きのドラッグを選ぶ。大きい文字の音声追加・使用は、確認前の保存禁止、対象ロットの選択、6個追加→2個使用→4個残りを検証する。

テストには既存のメモリ内DB・専用UserDefaultsを使う。撮影はテスト画像、拒否は注入された状態、音声は文章入力である。実機のカメラ・マイク・OS許可・音声認識の検証とは扱わない。

入力完了後の値の保持、確認前の保存禁止、入力欄全体が完了操作より上に見えること、同意取り消し後の再表示、Undoと関連フローの復帰を確認した。最大文字の文章末尾と数量入力を目視し、Git管理外の`tmp/previews/narrow-voice-typing.png`／`narrow-receipt-quantity.png`へ保存した。追加した最大文字の音声追加・使用テストは、Undo案内の配置変更前のSEと、変更後の標準幅で成功している。変更後のSEにおける同テストの再実行は今回の7件に含まない。

iPhone向けarm64 Releaseビルドは`CODE_SIGNING_ALLOWED=NO`で成功。ログは`/tmp/kyounanitaberu-narrow-device.log`、生成アプリの最低対応は17.0。署名・実機インストールは未実施。AppIntents未使用メタデータの警告、未整理のiPad回転設定は別の残件。

テスト用プロセスを終了して、引数なしの通常起動へ戻した。通常ストアの6モデル件数（64／0／19／19／1／2）がテスト前後で一致することを読み取り専用で確認。全レコード内容の比較ではない。通常の同意・OS許可は変更していない。元のdata/・design/・scripts/と旧iCloud制作フォルダは変更なし。Node.jsは不要・未導入。変更は未コミット。
