## 起動準備

1. 自分のiPhoneをMacへ接続し、Xcodeで`KyouNaniTaberu.xcodeproj`を開く。
2. アプリターゲットのSigning & Capabilitiesで自分の開発チームを選ぶ。
3. `KyouNaniTaberu`スキームの実行先に接続したiPhoneを選んでRunする。信頼や開発者モードの案内が出た場合は端末側で対応する。
4. 通常起動には`--ui-testing`などのテスト引数を付けない。テスト引数付きの画面で、実際の権限・通知・永続保存が動作したと判断しない。

検証用の食材だけを用意する。実機に既存データがある場合、初期化や全削除で権限を戻そうとしない。OSの許可状態はアプリ内の全削除では変わらない。

## レシートのカメラ撮影（2026-10-02追加）

全体のプライバシー説明とレシート利用説明はv2。説明への同意とOSのカメラ許可は別。撮影にはマイク・動画・写真ライブラリ全体へのアクセスを使わない。

| 確認 | 操作と成功条件 | 実機結果 |
|---|---|---|
| 初回許可 | レシートの説明v2へ同意し「レシートを撮影する」を押す。ここでカメラの許可を求め、許可画面終了後にアプリが操作可能へ戻ってから撮影画面を開く | 未実施 |
| 撮影・撮り直し・中止 | 静止画を撮影して採用する。標準撮影画面で撮り直せる。中止した場合、既存の確認中の項目を保ち、在庫は更新しない | 未実施 |
| OCRと確認 | 採用した写真を読み取り、商品名・数量の候補を表示。確認スイッチ前に保存できず、確認後だけ在庫へ反映する | 未実施 |
| 拒否・制限 | OS許可を拒否しても写真選択・手入力が使え、手入力中の項目を失わない。拒否なら設定への導線を示す | 未実施 |
| アプリを離れる | 撮影中にホーム・ロック・コントロールセンターへ移ると中止。戻っただけでは撮影を再開しない。許可中に背景へ移った場合も遅い許可応答から開かない | 未実施 |
| 画像の扱い | 撮影画像が写真ライブラリへ追加されず、アプリで画像ファイルを作らない。画像は向きを補正して長辺3000px以下へ整え、元の位置・撮影情報を引き継がず端末内OCRへ渡す | 未実施 |
| オフラインと多様なレシート | ネット接続なしで撮影と読み取り。縦長・傾き・薄い文字・暗い場所を確認し、読めない項目は手入力で修正できる | 未実施 |
| v1からの移行 | 説明v2の確認が必要になっても、在庫・買い物・初期登録完了状態を保持する。v1のレシート同意だけでは写真選択・撮影を表示しない | 未実施 |

シミュレータのUIテストでは`--ui-testing`と`--ui-camera-fixture`を組み合わせ、メモリ内で作った画像を実際のVision OCRへ渡す。`--ui-camera-denied`は拒否を再現する。どちらも通常利用では有効にならず、カメラ・写真ライブラリ・OS許可を変更しない。撮影機器や実際のOS許可画面の動作検証にはならない。
