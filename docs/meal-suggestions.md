# 献立候補の評価と表示

ホームは1人分で評価した主食・主菜の候補を、第一候補1件と代替4件で表示する。レシピ一覧は主食・主菜と汁物・副菜の区分を保つ。各候補に一致度、買い足し品、量の要確認品を表示し、詳細では1〜4人分に合わせて再計算する。候補がない場合もレシピ一覧と食材登録へ進める。

## 現行の並び順

1. 必須材料の在庫一致度が高い。
2. 一致度が同じ場合、量の確認が必要な必須材料が少ない。
3. さらに同じなら、同梱レシピの準備＋調理時間が短い。
4. 最後は固定レシピキー、UUIDで順序を固定する。

主食・主菜で、activeのレシピだけがホーム候補になる。汁物・副菜を第一候補へ混ぜない。順位は在庫の現在値から計算し、スコアをDBへ保存しない。複雑な重み付け、好み・アレルギーによる自動除外、自由なAIレシピ生成は追加していない。

これは設計書の「在庫と最も一致する第一候補」を満たす現行方式で、最終的な推薦条件は料理内容・分量のレビューと利用者の確認で調整する。期限を順位や第一候補の提案理由へ混ぜず、設計書どおり独立した在庫一覧に出す。解凍時間による順位補正も行わない。

## 一致度と必要量を分ける

一致度の分母は、在庫管理する必須材料の品数。任意材料と水などのignored材料を除く。分子は、既存のRecipeAvailabilityによって必要量を満たすと判定した材料と、有効な「ある」の在庫がある材料の品数。

- 正確な量は変換できる単位だけで合算する。g/kg、ml/L以外を推測換算しない。
- 数量不足が確定したものは「買い足し」として品数・名前を表示する。
- exact材料の「ある」「少ない」と、換算できない正確在庫は必要量を保証せず「量を要確認」として分ける。
- 「ある」は一致に含み、「少ない」は単独では一致に含めない。量が足りる正確な在庫もある場合は、正確量で充足を判断する。
- presence材料は既存の有無判定に従う。任意材料を強制的に買い足しへ入れない。
- 標準食材のUUIDで対応付ける。自分用食材を名前だけで標準材料へ推測対応させない。

例：ごはんとツナ缶を「ある」、マヨネーズとしょうゆをpresenceの「ある」で登録すると、ツナマヨ丼は食材一致100%（4/4品）になるが、ごはん・ツナ缶の2品は量の確認が必要。「必須材料は冷蔵庫にそろっています」とは表示しない。

必須材料が全てavailableで、分母が0でない場合だけ「必須材料は冷蔵庫にそろっています」を表示する。一致度100%だけを根拠に買い足し不要とは言わない。要確認の材料は不足量を断定しない。詳細でも数量不足の表示と「不足量は要確認」を分ける。

ホームと一覧は1人分で評価する。詳細は選んだ人数とレシピのbaseServings・scalingに従う。人数が増えれば一致度と不足分も変わり、献立決定後の買い物リストは同じ既存の在庫計算から作る。

## 期限と冷凍の扱い

期限切れ・取り除いた在庫は評価から除く。期限当日は利用可能として扱う。ホームの「期限が近いもの」は今日から2日後までの暦日を含み、「期限切れ（献立の計算対象外）」は別に表示する。量0、「ない」、取り除いた在庫をどちらの一覧にも出さない。期限なしから期限を推定しない。

各一覧は最初の5件を表示し、残りは展開して確認できる。自分用食材も実際の名前を出し、各行から編集へ進める。画面表示時、active復帰時、日付・時刻の大きな変更通知で評価日時を更新する。

使える冷凍在庫がある材料は「解凍が必要」または「凍ったまま調理」を表示する。量0の冷凍在庫だけを理由に解凍の案内を出さない。表示時間はレシピ原稿の値を使い、追加の解凍時間を自動加算しない。

## 実装と確認

App/Domain/RecipeSuggestions.swiftはSwiftDataに依存せず、レシピ・食材識別・StockLotの値を受け取る。RecipeAvailabilityの単位／数量計算を再利用し、matchesもservings・baseServingsを受け取るようにした。Home・一覧・詳細は同じ評価結果を表示する。元のJSON・design・scripts、SwiftDataの6モデル／スキーマ、購入・調理・Undoの保存処理は変更していない。

単体12件は曖昧状態、換算不可、対応する換算、baseServingsと人数、任意・ignored、期限切れ・削除・量0・独自食材、順位の優先順、安定した同点順、冷凍、期限の暦日境界、分母0、同梱40品を検証する。UI2件は100%でも要確認の表示、期限切れと期限間近の分離、人数変更後の一致度・不足2品・買い物の実数量を検証する。

UI用の--ui-suggestion-fixtureと--ui-suggestion-exactは、--ui-testingのときだけメモリ内の専用在庫を用意する。通常ストアや機能同意・OS許可は変更しない。
