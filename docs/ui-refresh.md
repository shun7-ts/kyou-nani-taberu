# UI整理・食材検索・調理後の在庫（2026-10-04）

ホームと候補カード、レシピ詳細を共通の料理画像と情報アイコンで整理し、食材検索と調理後の入力を短くした。ユーザーが実機で起動を確認した後に指定した変更を実装した記録。

## 画面

- ホーム上部は「今日何にする？」。
- 第一候補・他の候補・レシピ一覧・詳細に同梱の共通料理画像を表示。生成した料理のイメージであり、個々のレシピ写真ではない。「イメージ」を表示し、画像は装飾としてVoiceOverから除外する。オフラインで表示できる。
- 他の候補は通常文字で76ptの小さな写真と説明を横並び。アクセシビリティ文字サイズは縦並びにして説明を折り返す。
- 時計＝調理時間、冷蔵庫＝食材一致、買い物カゴ＝買い足し、注意アイコン＝在庫量の確認。品数や材料名を併記し、色・アイコンだけで意味を伝えない。時計と食材一致は幅に応じて横／縦配置を選ぶ。
- 「必ず使いたい食材」を「食材を選ぶ」へ変更。「スーパーで見つけた食材も選べます。」は削除。選んだ必須材料を含む料理へ絞る計算条件は維持。
- 詳細は料理画像・タイトル・短い説明、人数と在庫情報、材料／作り方を整理。材料行は必要量とアイコン付きの在庫状態・不足量を表示する。
- 献立決定の完了表示は「買い物リストに○品を追加しました。」に統一。品数は保存処理の結果を表示する。

## 食材と検索

- 元の `data/ingredient-master-v1.json` は64食材のまま保持する。アプリに追加データ `App/Resources/ingredient-additions-v1.json` を同梱し、読込時に結合・検証する。結合後のカタログ版は1.4.0、食材72件（水を含む）。
- 追加：ほうれん草、ブロッコリー、トマト、なす、レタス、れんこん、ごぼう、さつまいも。
- 既存64食材のUUID・固定キーは変更しない。追加は予約UUID末尾65〜72を使い、繰り返し取込で重複させない。既存の在庫や自分用食材は保持。
- 漢字名には管理された読み・別名を補う。検索はかな・全半角・英字大小を正規化し、部分一致を使う。複数の検索語はすべてがいずれかの名前・別名に含まれる条件。
- 適用先はホーム／レシピ一覧からの食材選択、初回一括登録の検索、冷蔵庫検索。例：とりもも／トリモモ／ﾄﾘﾓﾓ、ぎゅうにゅう／牛乳、ほうれん／ほうれん草。
- 追加食材は登録・検索用。40品のレシピ内容は今回増やしていないため、追加食材を指定した料理がない場合は該当なしを表示する。未知の食材を名前の近さだけでレシピ材料へ割り当てない。

## 調理後

- 正確な数量の食材では「使った量／残りの量」を選べる。初期値は選んだ人数とレシピのbaseServingsに合わせた使用量。モード切替時は換算可能な現在庫から反対の量を計算し、同じモードを選び直しても値を変えない。
- 「在庫○ → 残り○」の短いプレビューと「在庫を更新」ボタン。入力中は「入力を完了」を表示し、キーボードを閉じた後に保存する。
- 残りの量を入力した場合は、保存時の利用可能な在庫合計との差を使用量へ変換し、既存の期限順消費を使う。数量超過・負数・非有限値を拒否する。量不明の在庫が混在する場合や単位を換算できない場合は残量を推測しない。
- 数量が不明で正確在庫がない通常食材は、使用量0を入力させずに「ある／少ない／ない」の状態のみ更新する。
- 調味料またはpresence材料は数量入力を表示せず「ある／少ない／ない」を選ぶ。複数の在庫がある場合はロット別に表示し、期限切れ・削除済みは更新しない。在庫未登録の場合は「在庫なし」を表示し、自動的な在庫作成は行わない。
- 数量で登録されていた調味料も、調理後に選んだ状態で保存する。数量を状態管理へ切り替えるため、保存後は正確な残量を保持しない。取り消しでは元の数量・単位へ戻せる。
- 全材料を検証してから一括保存する。献立の二重調理拒否、失敗時の全件復元、履歴、Undoの仕組みとSwiftDataの6モデルは維持する。
