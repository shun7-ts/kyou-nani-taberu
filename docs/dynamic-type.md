# 認識入力画面の大きい文字

レシートの正確数量と単位は、通常の文字サイズでは横並びを保ち、アクセシビリティ用の文字サイズでは別々の行に表示する。数量欄が単位ピッカーに押されるのを防ぎ、文字・数量・確認の操作へスクロールして進める。

アクセシビリティ用のサイズでは下部の保存ボタンを「1品を登録」「1件を反映」のように短く表示する。件数は実際の選択項目から計算し、読み上げ向けのラベルには従来の「確認した1品を冷蔵庫へ登録」「確認した1項目を反映」を保持する。通常サイズの文言は保持する。文字サイズを上限で制限したり、読めるサイズへ縮小したりしない。

「入力を完了」は引き続き入力中だけ表示し、キーボードを閉じても文章・名前・数量を保持する。フォーカス変更時とキーボード表示後に入力欄を上部へスクロールし、下部操作の裏に隠れたまま入力させない。安定した入力IDをScrollViewReaderで参照する。入力中だけ文字サイズに応じた末尾の余白を確保し、最後の入力欄もキーボード上へスクロールできるようにする。確認スイッチを通す前に保存できない。SwiftDataモデル・スキーマ、JSON、認識・在庫保存処理、同意・OS許可は変更していない。

## 検証方法

アプリ起動引数の`-UIPreferredContentSizeCategoryName UICTContentSizeCategoryAccessibilityXXXL`で、そのプロセスの文字サイズを最大へ指定する。シミュレータ全体の設定を変更しない。既存の`--ui-testing`でメモリ内DBと専用UserDefaultsを利用し、通常の永続ストアを検証用へ置き換えない。数量欄の高さが40ptを超えることもテストで確認し、文字サイズの指定が反映されていることを確かめる。

- 最大文字・ライトの音声画面：日本語文章を直接入力→キーボード表示中の文章欄がナビゲーションと完了操作の間に見えることを確認→キーボード完了→文章保持→候補作成→数量欄の完了→未確認の保存禁止→破棄後の在庫不変。
- 最大文字・ダークのレシート画面：食材名と数量2を入力→各キーボード完了→値の保持→確認→2個の保存。最大文字では入力・確認・保存を対象にし、カメラ拒否時の代替は通常サイズの既存テストで検証する。

フォームのスクロールは固定の保存ボタンやキーボードを避けた領域で行う。最大文字では説明や入力行が増えるので、回数を増やすだけでなく、対象とナビゲーション・固定操作の位置を見てスクロール方向を決める。通常サイズの同じ入力フローも回帰検証する。

今回の範囲は認識入力画面の通常サイズと最大サイズ。中間サイズ、狭いiPhone幅、他の画面全体、実機・iOS 17・外付けキーボード、実際のVoiceOver読み上げは別途確認する。ラベルの保持だけでVoiceOverの実動作検証が完了したとは扱わない。
