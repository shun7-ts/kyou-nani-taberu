# 食材追加の検索とカスタム入口（2026-10-06）

マイ冷蔵庫の＋、手入力、ホームの食材登録は同じ追加フォームを開く。標準食材の長いPickerを、最初の画面で名前・別名・かなから検索して選ぶ方式へ変更。検索に一致する有効な登録対象マスターを表示し、候補を明示的に選んだ後に数量／単位／保存方法を既存の初期値へ切り替える。選択前は保存不可。選び直しは「変更」、検索のクリアと「一覧から選ぶ」も用意。生魚／缶詰等は名前だけで自動確定しない。検索欄は追加画面内、検索によって在庫を自動作成しない。

「自分用の食材」は「カスタム食材」へ統一し、標準検索の下に小さな文字の入口を配置。押すと自由な名前と任意の対応付けを入力できる。登録の接触領域は44pt以上を保持。検索語からカスタムに切り替える際は名前に引き継ぐ。標準食材モードへ戻れる。初回一括登録・認識画面・削除／説明の名称も揃える。カスタムのみの登録と既存のカスタム編集を維持。

レシピ材料の在庫評価「あります」は「あり」へ短縮。曖昧状態の既存「ある・少ない・ない」と在庫計算は維持。

## 献立の食材選択について

ユーザーはカスタム食材を最初は表示しなくてもよいか意見を求めている。通常の献立選択は標準食材だけにし、カスタム対応付けは登録／編集の補助に寄せるのが提案。検索→料理という流れで対応付けを考える負担を減らせる。一方、既に対応付け済みのカスタム在庫は標準食材として評価する必要がある。今回、献立のカスタム選択機能を削除／非表示にはしていない。見出しだけ「カスタム食材」へ変更、以前の標準食材への対応付けを保持する。

## 買い物リストから冷蔵庫へ

「買うものを追加」の先頭に「食材を選ぶ」を追加し、検索可能なマスター一覧から食材を選べる。選択した固定IDと単位を保持して買い物へ追加し、購入チェック→「購入品を確認」→一括保存で冷蔵庫へ追加できる。購入チェックだけでは在庫を増やさず、数量・保存方法・任意の期限を確認する既存の1ページを利用する。

自由入力の品名も保持する。入力後に名前がマスターと一致しなくなった場合は食材IDを解除し、曖昧な一致は候補から選ぶ。日用品は購入確認で在庫対象から除外でき、未知の食材にはカスタムとして登録する既存導線を残す。食材を選んだときにonChangeでIDが誤って解除されないよう修正した。
