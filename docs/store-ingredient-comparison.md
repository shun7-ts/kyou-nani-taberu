# スーパーで見つけた食材と冷蔵庫で料理を選ぶ

> 2026-10-04の実機レビュー後、お店で買う予定と量比較のUIは削除した。以下は以前の仕様・検証記録。現在の画面は[browse-and-inventory.md](browse-and-inventory.md)を参照。
半額などで買いたい標準食材を選び、「お店で買う予定」をオンにする。買う食材を必須材料として使う料理に絞り、残りの材料を冷蔵庫と比較する。価格・値引き率の入力や商品写真の認識は追加していない。

購入量を指定する機能を2026-10-04に追加した。量指定時の判定・買い物へ全量を引き継ぐ仕様は[store-purchase-amount.md](store-purchase-amount.md)を正本とする。以下は量未指定時の比較と2026-10-03の検証記録。

## 比較と必要量

ホーム・レシピ一覧・詳細で購入予定の食材を引き継ぐ。購入予定の食材を在庫一致の分母から除き、「ほかの食材一致」を表示する。その食材の量をそろえることが前提の比較であり、実際の在庫が増えた意味ではない。その他の必須材料がない場合は「ほかに必要な材料はありません」と表示する。

他の材料の一致度が高い順に候補を並べる。同率の場合、このモードだけ追加の不足品数が少ない順を優先し、その後は要確認数・調理時間・固定キーの順。通常モードの順位は維持する。期限切れ在庫を使わず、曖昧な「ある」は量の要確認を残す。

「買う予定：食材名（料理の必要量：○g・○人分）」と、選んだ食材以外の追加の買い足しを分けて表示する。必要量は購入する商品の数量の推測ではない。詳細で1〜4人分を変更すると必要量とその他の不足分を再計算する。売り場のパック・缶・重さが必要量を満たすかはユーザーが確認する。

購入予定食材が手元に十分ない状態で、全材料が冷蔵庫にあると表示しない。冷蔵庫の実際の状態・正確な不足量は計算結果に保持する。購入前にInventoryItemやInventoryEventを作成しない。

## 買い物・購入後（量未指定）

献立決定は既存MealServiceを使用し、購入予定の食材を含む実在庫との差分を買い物に追加する。既に冷蔵庫にある同じ食材の分は差し引く。例えば2人分の必要量がツナ缶2缶で冷蔵庫に1缶あるなら、比較画面では料理の必要量2缶、買い物には不足1缶が入る。曖昧な量は要確認のまま。

チェックと購入確認を経て在庫に反映する既存の流れは変更しない。比較・献立決定だけで在庫や購入済みの状態を更新しない。条件を解除すると買い物中の比較もオフになる。選択状態は画面内のみで、再起動後の保存は行わない。
