# 音声でまとめて在庫登録（2026-10-07）

開発場所は `${HOME}/Developer/IOSアプリ制作`。外部サービスへ音声を送らず、日本語の端末内Apple Speech認識を維持する。録音・発話全文は永続保存しない。

## 使い方

マイ冷蔵庫 → 音声 → まとめて話す → 一覧にする → 必要な項目だけ直す →「N件を登録」。名前だけなら「あり」、数量を話せば数量、調味料は「あり・少ない・ない」。手入力も同じ解析を使える。

「卵が6個、玉ねぎが半分、鶏むねが300グラム。牛乳とキャベツもある。しょうゆは少なめ」を6食材の候補に分解する。食材の最長別名を優先し、トマト／とうもろこしや、リットルに含まれる「と」で分割しない。「鶏むね」「鶏もも」は肉の省略名として扱う。「にんじん2本」など一部の丸ごとの食材の本数は、食材マスターの個数へ対応させる。一般的な個↔本の換算は追加しない。

一覧は食材名・量・確認状態を表示し、タップした行だけ開いて編集する。通常の一致候補に確認スイッチはなく、最後の登録操作を一括確認とする。未対応語は一覧に残し、初期状態では登録対象外。曖昧な数量・単位や異なる重複量は確認・修正または除外が必要。数量の推測、未発話食材の削除、期限の推定はしない。「1個半」など未対応の複合数量、概数や範囲、数量と「ない」の矛盾も確認対象にする。「卵と牛乳はありません」の共通状態は両方へ反映し、句読点の後の「じゃなくて」の言い直しは直前の候補を要確認にする。

1回の録音は従来通り30秒まで。「追加で話す」で文章を継ぎ足せる。確認一覧を作った後の追加入力も、既存の編集済み候補を保持して追加する。追加分を一覧にするまで登録ボタンは無効にする。同じ食材・同じ量はまとめ、違う量は1行の要確認候補にする。上限は20候補・4,000文字。

## 既存在庫の扱い

- 同じ食材が1在庫なら、残量を更新する。加算・別在庫の自動作成はしない。
- 「あり」だけの発話では、正確な正の数量を維持する。ゼロや「ない」の在庫は「あり」に戻せる。
- 複数在庫なら更新先を選ぶ。選ばなかった在庫や発話しなかった食材は変更しない。
- 既存の購入日・期限・期限種別は維持。保存方法は発話または編集で指定した場合だけ変更する。
- 確認後に在庫の増減・削除・更新があった場合は候補の作り直しを求める。
- 全件を1トランザクションで保存。セッション印で二重保存を防ぎ、既存の取り消し機能の対象になる。

明示的な「買った」「使った」などは従来の操作・対象・量の確認フローへ自動で渡し、残量と購入量を混同しない。

認識結果が無音で確定したとき、マイクを閉じずに次の認識区間を始める。確定済みの文章を保持して次の発話を改行で追加する。録音全体の30秒上限、明示的な終了、画面離脱・割り込みでの停止を維持する。認識区間が切り替わる前の遅い結果は採用しない。

一覧では各候補の左側の×でその1件を削除できる。誤認識の食材を消すために一覧全体を作り直す必要はない。曖昧な候補を一時的に登録対象から外す操作は維持。「入力内容」のモード選択、確認中の「文章から作り直す」と「文章を編集する」は削除した。初回の手入力と「一覧にする」、候補作成後の「追加分を一覧にする」は維持する。

将来のLLM利用案：まずAppleの端末内音声認識で文字にし、既存の食材辞書と在庫候補を使って食材・数量・操作だけを構造化する。辞書や明確な規則で確定できない候補に限ってLLMを使い、「元の発話」「候補食材ID」「数量・単位」「操作」「要確認理由」の決まった形式へ変換する。出力は食材マスターや単位と照合し、不明な量や低確信の名前を推測で補わず、ユーザーに候補一覧で確認してもらう。LLMは文字にならなかった音声を復元できないため、まず端末内認識・食材名ヒント・実機での発話比較を評価する。Appleの[Foundation Models](https://developer.apple.com/documentation/FoundationModels)は26.0以降・Apple Intelligence対応端末で利用可能かを確認し、[guided generation](https://developer.apple.com/documentation/foundationmodels/generating-swift-data-structures-with-guided-generation)で構造化できる。現在のiOS 17対応と端末内・外部非送信の説明を維持するため、LLM導入は別設計とし、対応端末・OS、利用者の同意、非対応端末の既存解析へのフォールバックを検討する。今回LLMや外部送信は追加していない。

## 認識改善と限界

食材マスターの名前・別名から最大100語の `contextualStrings` を音声認識へ渡す。既存在庫と一般的な食材を優先し、端末内日本語認識の条件は維持する。仕様の出典：[Apple SFSpeechRecognitionRequest.contextualStrings](https://developer.apple.com/documentation/speech/sfspeechrecognitionrequest/contextualstrings)。

今回の自動テストは文字列からの構造化・保存・画面操作・認識クライアントの制御であり、実際の日本語音声の精度を保証するものではない。iPhoneで通常の話し方を試し、「聞き取った文章の誤り」と「食材・数量への分解の誤り」を分けて確認する。元の発話を保存する計測機能は追加していない。

## 実機での比較項目

| 発話 | 確認すること |
|---|---|
| 卵、牛乳、キャベツ、豆腐、納豆 | 5候補。数量なしで登録できる |
| 卵6個、玉ねぎ半分、鶏むね300グラム | 6個／0.5個／300g |
| トマトととうもろこし、牛乳1リットル | 名前とリットルを壊さない |
| しょうゆ少なめ、みそはある、塩はない | 3状態 |
| 卵6個、卵3個 | 加算せず要確認 |
| 牛乳半分、未知の食材 | 確認候補と未対応語が残る |
| 認識後に追加で話す | 前の候補・編集値を保持し、新しい食材を追加 |
| 正確な量のある食材を名前だけ話す | 数量・購入日・期限を維持し、在庫を増やさない |

同じ発話を静かな部屋／冷蔵庫の動作音がある環境で数回ずつ比較する。権限拒否・中断・機内モードも既存の実機確認表に沿って確認する。実機へはXcodeで接続iPhoneを選んで⌘R。
