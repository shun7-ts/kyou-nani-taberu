# ホーム・冷蔵庫・買い物の大きい文字

## 変更した表示

アクセシビリティ用の文字サイズでは、冷蔵庫の保存方法・種類・並び順を別々のメニュー行へ配置する。項目名と現在の値を縦に表示し、横並びで値が「…」になる問題を解消する。買い物の表示フィルターも同じ形式にする。通常サイズでは既存のセグメントとピッカーを保持する。

在庫の食材名・保存方法／種類・数量・期限を、大きい文字では縦に並べる。ホームの期限行も食材名と期限を縦に配置する。ホームのタイトルは大きい文字でinlineにして、狭い画面での省略を避ける。候補の説明と買い物行は内容の高さに合わせて折り返す。文字サイズの上限固定や縮小は行わない。

目視で、献立決定後の固定案内と調理ボタンが画面の大半を使い、完了説明も省略される問題が見つかった。大きい文字では完了件数・買い物タブの案内・調理確認操作をスクロール可能なレシピ詳細の先頭へ移す。献立決定後はその案内へ移動する。固定操作は短い「献立を決定」に絞る。買い物の下部操作は「1品を確認」のように件数を保持して短くする。両ボタンのaccessibilityLabelは従来の説明を保持する。通常サイズの完了案内は従来の位置・説明を保持する。

変更範囲は表示・一時的な完了件数の保持・UIテスト。候補順位、一致度、数量計算、在庫／購入／調理／Undoの保存サービス、SwiftDataスキーマ、同梱JSON、機能同意・OS権限は変更していない。

## 検証方法

Xcode 27.0 / iOS 27.0の専用iPhone SE（第3世代）、375×667ptで、最大のアクセシビリティ文字サイズを検証する。指定はアプリプロセスの起動引数だけで、シミュレータ全体の文字サイズ設定は変更しない。

UIテストは既存のメモリ内DBと専用UserDefaultsを使う。食材6品の専用在庫で、以下を確認する。

- ライトのホーム：一致100%でも量の要確認2品を表示し、期限間近と期限切れを分け、期限切れの食材から編集へ移動する。
- ダークの冷蔵庫：種類と名前順、冷凍の空状態、冷蔵へ戻した結果、選択値、牛乳500ml・期限の表示と編集を確認する。
- ダークの献立・買い物：2人分へ変更すると一致度50%・不足2品へ更新。献立決定後の件数案内がナビゲーションと固定操作の間に収まり、調理確認へ移動・キャンセルできる。買い物の購入済み／未購入で対象を絞り、2品の購入確認へ移動・キャンセルしてチェック状態が残る。

システムメニューでは、大きい文字の選択肢が画面外に仮想化されるため、メニュー内をスクロールして選ぶ。人数変更はStepper全体の位置に頼らず、増加ボタンの位置へ移動する。数量欄の「500.0」と「500」は数値として比較する。画面に収まる説明・在庫・買い物行は上下端を確認する。ナビゲーション直下の行に余分な隙間を要求せず、位置の丸め差を許容する。買い物では高速ドラッグの慣性で行き過ぎるため、ゆっくり移動して停止する。
